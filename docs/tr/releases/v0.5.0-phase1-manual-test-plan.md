## 2. Ortam kapısı

1. Repository kökünde `git branch --show-current` çalıştırın; sonuç
   `codex/mesh2d-mesh0` olmalı.
2. Doctor kontrolünü çalıştırın:

   ```bash
   npm run --silent chorono -- doctor --project /Users/nilayerol/developer/caamtscr/chorono-editor --json
   ```

3. 2000 portundaki başka projeyi durdurmayın. Test build'ini 2010'da başlatın:

   ```bash
   CHORONO_MCP_ENABLED=1 npm run start -- --hostname 127.0.0.1 --port 2010
   ```

4. `http://127.0.0.1:2010` adresini açın. MCP kanıtı da alınacaksa editörde
   **MCP → Connect this editor** seçin.
5. Tarayıcı geliştirici konsolunu açık tutun. Senaryoyla ilişkili exception,
   unhandled rejection veya sürekli warning oluşursa sonucu FAIL yazın.
6. Her test paketi için temiz proje ya da kılavuzdaki ilgili kabul fixture'ını
   açın. Önceki paketin sahne değişikliklerini taşımayın.

Ortam kapısı geçmeden özellik testine başlanmaz. Ortam sorunu varsa FAIL değil
BLOCKED kaydedilir.

## 3. Koşu A — hızlı smoke

Bu koşu her yeni commit grubundan sonra uygulanır. Sırayı değiştirmeyin:

1. `MESH-01`: Structured Grid oluşturun; triangle overlay'i açıp kapatın;
   final görüntüye sızmadığını kontrol edin.
2. `TEX-01`: Texture atayın; fit/cover durumlarını değiştirin; canvas üzerinde
   sürükleyerek offset verin; sayısal alanların aynı değeri gösterdiğini görün.
3. `DEFORM-01`: Hazır binary clip'i oynatın; pause/scrub/loop sonrasında mesh
   şeklinin ve texture'ın birlikte hareket ettiğini görün.
4. `BAKE-01`: Track Bake preview oluşturun; Apply, Undo ve Redo uygulayın;
   preview ile commit edilen hareketin aynı olduğunu kontrol edin.
5. `PHYSICS-UI-01`: Rigid Preview başlatın; Jobs & Bake panelinde aynı job'u
   görün; Apply ve Undo yapın.
6. `PHYSICS-UI-02`: Voronoi preview'da fracture tick'inin hemen öncesi ve
   sonrasına scrub edin; source/fragment geçişinin atomik olduğunu görün;
   Discard'ın sahneyi değiştirmediğini kontrol edin.
7. `PHYSICS-UI-16`: Bond seçin; Strength/Damage/Unbreakable veya fixed-tick
   action bilgisini Inspector ile eşleştirin.
8. `PHYSICS-UI-17`: Recursive fixture'da 399, 600, 800 ve 1000 ms karelerini
   inceleyin; ikinci event sonrası parent yerine child fragment'ları görün.
9. `RENDER-01`: Chorono Render yokken tek kare PNG alın; backend bilgisinin
   Built-in/fallback olduğunu doğrulayın.
10. `PORTABLE-01`: Kaydedin, temiz açın, aynı frame'i tekrar render edin;
    layer/asset/bake/topology bilgisinin korunduğunu doğrulayın.

Koşu A'da herhangi bir FAIL varsa tam regresyona geçmeden sorun kaydedilir.

## 5. Koşu C — Öncelik 10 kabul kapısı

Öncelik 10 geliştirmesi tamamlandığında aşağıdaki testler zorunludur:

1. Aynı fixture'ı File, JSON ve MCP yollarıyla içe aktarın; stable layer/asset
   kimlikleri ve scene ayarlarını karşılaştırın.
2. Import → save → load → export round-trip yapın; desteklenen veride kayıp,
   sessiz migration veya farklı default oluşmamalı.
3. Seçili kareyi viewport, player, Built-in final render ve Chorono Render ile
   alın; target resolution, background, alpha ve frame time aynı olmalı.
4. Tek kare PNG ile PNG sequence'in ortak karesini pixel veya açık toleransla
   karşılaştırın.
5. Chorono Render'ı erişilemez yapın; fallback ve uyarıyı doğrulayın. Yeniden
   erişilebilir yapıldığında önceliğin Chorono Render'a döndüğünü görün.
6. FRACTURE0–3 ve MeshDeformation içeren portable fixture'larda final render'ın
   viewport/player ile aynı topology event'ini kullandığını kontrol edin.

Bu kapının ayrıntılı fixture ve toleransları geliştirme commit'iyle birlikte
kılavuza eklenmeden Öncelik 10 tamamlanmış sayılmaz.

## 6. Koşu D — Öncelik 11 kabul kapısı

Mevcut çıktı otomasyon MVP'si tamamlandığında:

1. Current frame, range ve full timeline işi oluşturun.
2. İki işi sıraya koyun; bounded/serial yürütme ve görünür queued/running
   durumlarını doğrulayın.
3. Çalışan işi iptal edin; yarım çıktı manifestte tamamlanmış görünmemeli.
4. Başarısız işi Retry ile tekrar çalıştırın; source revision ve ayarlar
   değişmeden deterministik sonuç alın.
5. İş çalışırken sahneyi değiştirin; frozen source veya açık stale tanısı
   görünmeli, sessizce karışık revision render edilmemeli.
6. PNG sequence ve Chorono Render MP4 çıktılarının progress, warning, output
   path ve manifest kayıtlarını doğrulayın.

Responsive variants, data binding, audio/caption pipeline ve sınırsız paralel
queue bu kapıda aranmaz; bunlar Faz 2'dir.

## 7. Koşu E — Öncelik 12 release kapısı

1. Temiz checkout/install üzerinde `npm test`, `npm run mcp:build` ve
   `npm run build` çalıştırın; Next sunucusunu build öncesi durdurun.
2. Koşu A ve bütün Koşu B'yi temiz projelerle yeniden çalıştırın.
3. MCP bağlı temiz projede rigid, FRACTURE0, FRACTURE2 bond action ve
   FRACTURE3 recursive bake oluşturun; validate ve portable save yapın.
4. Uzun timeline ve büyük fixture ile memory/cache artışını izleyin; iş bitimi
   veya proje resetinden sonra kaynakların bırakıldığını doğrulayın.
5. Package sürümü, changelog, Türkçe/İngilizce release notu ve bilinen uyarı
   listesini doğrulayın.
6. Release adayı için PASS/BLOCKED/FAIL toplamı çıkarın. Açık release blocker
   varken tag veya yayın yapılmaz.

Bir FAIL kaydında şunlar bulunmalıdır:

- temiz projede tekrar üretim adımları;
- beklenen ve görülen davranış;
- layer/asset/job kimliği ve timeline zamanı;

- render/export backend'i;
- mümkünse portable proje ve ekran görüntüsü.
