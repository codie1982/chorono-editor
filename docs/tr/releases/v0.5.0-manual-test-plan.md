## 2. Ortam kapısı

1. Repository kökünde `git branch --show-current` çalıştırın; sonuç
   `codex/mesh2d-mesh0` olmalı.
2. Doctor kontrolünü çalıştırın:

   ```bash
   npm run --silent chorono -- doctor --project /Users/nilayerol/developer/caamtscr/chorono-editor --json
   ```

3. 2000 portundaki başka projeyi durdurmayın. Test build'ini 2010'da başlatın:

   ```bash
   CHORONO_MCP_ENABLED=1 npm run start -- --hostname 127.0.0.1 --port 2010
   ```

4. `http://127.0.0.1:2010` adresini açın. MCP kanıtı da alınacaksa editörde
   **MCP → Connect this editor** seçin.
5. Tarayıcı geliştirici konsolunu açık tutun. Senaryoyla ilişkili exception,
   unhandled rejection veya sürekli warning oluşursa sonucu FAIL yazın.
6. Her test paketi için temiz proje ya da kılavuzdaki ilgili kabul fixture'ını
   açın. Önceki paketin sahne değişikliklerini taşımayın.

Ortam kapısı geçmeden özellik testine başlanmaz. Ortam sorunu varsa FAIL değil
BLOCKED kaydedilir.

Yeni Mesh ek regresyonu için güncel checkout'un zaten çalışan `2001` editörü
de kullanılabilir. Bu durumda browser/port ve test edilen commit'i kaydedin;
ikinci sunucu başlatmayın. `2010` izole test adresidir, özelliğin şartı değildir.
Yeni kodun mevcut build'e dahil olduğu doğrulanmalı; yeniden build gerekiyorsa
önce ilgili Next sunucusu durdurulmalıdır.

## 5. Sonuç ve kanıt kaydı

Her senaryo için şu satırı doldurun:

| Tarih/saat | Commit | Senaryo | Sonuç | Browser/port | Kanıt | Hata/not |
| --- | --- | --- | --- | --- | --- | --- |
|  |  |  | PASS / FAIL / BLOCKED / NOT AVAILABLE |  | ekran görüntüsü veya çıktı yolu |  |

Bir FAIL kaydında şunlar bulunmalıdır:

- temiz projede tekrar üretim adımları;
- beklenen ve görülen davranış;
- layer/asset/job kimliği ve timeline zamanı;
- browser console mesajı;
- render/export backend'i;
- mümkünse portable proje ve ekran görüntüsü.
