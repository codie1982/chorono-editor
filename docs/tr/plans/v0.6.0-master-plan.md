# v0.6.0 — masaüstü uygulama ve çıktı ana planı

- **Taşıma kararı:** 22 Kasım 2026
- **Planın yazıldığı branch:** `codex/mesh2d-mesh0`
- **v0.6.0 geliştirme branch'i:** Henüz açılmadı; uygulama başlamadan ayrı
  branch adı bu belgeye işlenir
- **Hedef sürüm:** v0.6.0
- **Durum:** Planlandı; bağımlılık kapısı geçilmeden aktif geliştirme değildir
- **Plan sırası:** Bağımlılık kararı → masaüstü temel → **10 → 11 → 12**
- **Kapsam:** Masaüstü editör temeli, uygulama içine gömülü Chorono Render;
  canonical import/export, final render, çıktı job orkestrasyonu ve v0.6.0
  kalite kabulü

## 1. Sürüm kararı

10, 11 ve 12 aşamaları önce v0.5.0 Faz 1 kapanışı olarak düşünülmüştü. 22 Kasım
kararıyla bu kapsam v0.5.0'dan tamamen çıkarıldı ve v0.6.0'a taşındı. Nedeni;
render backend'i, codec/container, dosya/çıktı sahipliği, job worker'ları,
asset/font/audio çözümleme ve MCP job sözleşmeleri için yeni bağımlılık
kararları gerektirmesidir.

v0.5.0; mevcut Mesh2D, render backend seçimi/fallback, BakeService, rigid ve
FRACTURE0–3 teslimleriyle kapanır. Bu belge v0.5.0 release koşulu değildir.
FRACTURE4/5, emitter/particle, Cloth, Blob/liquid, smoke/fire ve Character
Motion ise [v0.10.0 ileri 2D planına](v0.10.0-advanced-2d-plan.md) taşınmıştır;
v0.7.0–v0.9.0 için aradaki işler ayrıca kararlaştırılacaktır.

Repository'deki ilgili girdiler:

- [3D öncesi tamamlama takibi](pre3d-completion-audit.md) eski ortak editör,
  viewport, input ve kaynak kapılarını kapatır; v0.5.0 çıktı teslimi değildir.
- [v0.5.0 elle kabul kılavuzu](../releases/v0.5.0-manual-acceptance-tests.md)
  mevcut teslimlerin regresyonunu verir; v0.6.0 çıktı hattını zorunlu kılmaz.
- [Canonical export/final render planı](export-consistency-2d-plan.md) doğru
  mimari hedefi verir; ileri renk, CanvasKit ve FP16 gibi sonraki araştırmaları
  da içerir.
- [Çoklu format](multiformat-production-2d-plan.md) ve
  [üretim otomasyonu](production-automation-2d-plan.md) belgeleri bu v0.6.0
  diliminden daha geniş ürün kapsamına sahiptir.

Bu belge v0.6.0 için plan kaydıdır. Bağımlılık kapısı onaylanmadan uygulama
başlamaz ve v0.5.0 branch'ine yeni çıktı altyapısı eklenmez.

Uygulamaya başlamadan önce aşağıdaki kararlar gerçek repository envanteri ve
küçük spike'larla kapatılır:

| Bağımlılık | Verilecek karar |
| --- | --- |
| Desktop shell | Electron/Tauri veya başka adayın bundle, startup, GPU/canvas, Node/native erişim, bakım ve lisans karşılaştırması |
| Next.js çalışma modeli | Static bundle, embedded local server veya hybrid shell; API route ve MCP yaşam döngüsü |
| Chorono Render | Render çekirdeğinin masaüstü uygulama paketine hangi workspace/runtime sınırıyla gömüleceği; editör frame sözleşmesi, sürüm uyumu, worker/process izolasyonu, progress/cancel, codec ve dahili fallback. v0.5.0'daki `/api/render/2d-sequence`, harici servis discovery/bearer ve `ChoronoRenderBridge` yalnız geçiş kaynağıdır; v0.6.0 ürün akışı bunları kullanıcıya bağımlılık yapmaz |
| Codec/container | MP4'ü paket içindeki hangi codec/runtime'ın ürettiği; platform, lisans, bundle, update ve hata davranışı |
| Dosya/çıktı sahipliği | Native open/save/reveal, geçici dosya, atomik tamamlanma, autosave ve crash recovery |
| Job/process yürütmesi | UI process, worker ve paket içi render/encode process sınırı; concurrency, cancel ve crash izolasyonu |
| Asset/font/audio/video | Portable dependency çözümleme, missing kaynak, offline davranışı ve izinler |
| Kaynak bütçesi | Frame buffer, encoded output, cache, disk ve memory preflight/admission |
| MCP | Masaüstü shell içinde aynı revision/job/status/cancel sözleşmesi ve bağlantı yaşam döngüsü |

Kapı çıktısı; seçilen adapter'lar, destek/fallback matrisi, yeni runtime/package
bağımlılıkları, platform sınırı, lisans notu, spike ölçümü, rollback planı ve
architecture decision record'dur. Shell seçimi veya process sınırı açıkken
genel masaüstü entegrasyonu ve Öncelik 10 başlamaz.

## 4. Masaüstü editör teslimi

### D0 — gerçek fixture ile shell spike

- Boş demo yerine Mesh2D, video/font asset, rigid/fracture bake, MCP bağlantısı
  ve gömülü Chorono Render MP4 çıktısı içeren gerçek proje kullanılır.
- Cold start, bundle boyutu, canvas/GPU uyumu, local server ihtiyacı, file API,
  child process, debugger/hot reload ve paket bakım maliyeti ölçülür.
- Chorono Render kodunun workspace modülü, native runtime veya paket içi worker
  olarak bağlanması karşılaştırılır. Her seçenek tek uygulama paketi, tek
  launcher ve tek güncelleme kanalı koşulunu korur; ayrı ürün kurulumu seçeneği
  değildir.
- Shell seçimi bu ölçümlerden sonra ADR ile sabitlenir.

### D1 — uygulama kabuğu ve proje yaşam döngüsü

- New/Open/Save/Save As/Recent Projects, dirty-state ve close confirmation.
- Portable proje ile kullanıcı workspace/cache/config dizinleri ayrılır.
- Autosave ve crash recovery açık sahiplik, sürüm ve temizleme politikası taşır.
- Menü, shortcut, pencere/focus ve çoklu pencere kararı platform adapter'ında
  tutulur; domain scene modeli shell import etmez.

### D2 — native servis adapter'ları

- Native file dialog, output folder, reveal/open ve güvenli atomik yazma.
- Render/encode process başlatma, bounded log, progress, cancel, timeout ve
  child crash izolasyonu.
- `EmbeddedRenderService` benzeri küçük bir uygulama adapter'ı gömülü Chorono
  Render çekirdeğinin initialize/render/progress/cancel/dispose yaşam döngüsünü
  sahiplenir. React, scene domain'i ve browser kodu process/codec ayrıntısına
  doğrudan bağımlı olmaz.
- v0.5.0'daki harici servis bearer/discovery akışı masaüstü ürün yolundan
  kaldırılır. Render çekirdeği ayrı process'te çalıştırılırsa port/token/process
  handle yalnız native adapter içinde kalır; kullanıcı kurulum veya bağlantı
  yönetmez ve sahipsiz process bırakılmaz.
- Aynı uygulama oturumunda gömülü Chorono Render başlatılamaz, çöker veya
  seçilen işi desteklemezse adapter tanılı biçimde dahili renderer'a düşer.
- MCP server/editor bağlantısı shell açılış/kapanış yaşam döngüsüne bağlanır.

### D3 — paketleme ve güncelleme

- Platform target matrisi, app ID, ikon, version/build numarası ve izinler.
- Chorono Render runtime'ı, codec bağımlılıkları ve gerekli lisans/notice
  dosyaları editör artifact'ının parçasıdır. Editör ile render çekirdeği ayrı
  kurulmaz ve ayrı güncellenmez; uyumluluk matrisi build sırasında doğrulanır.
- Debug ile signed release artifact açık ayrılır.
- Code signing/notarization, update channel, rollback, SBOM/third-party notice
  ve reproducible artifact manifest'i planlanır.
- İlk release platformları D0 sonucuyla seçilir; desteklenmeyen platform varmış
  gibi paket üretilmez.

### D4 — masaüstü kabulü

- Temiz makinede install/start/open/edit/save/render/reopen/uninstall smoke.
- Temiz makinede başka Chorono Render kurulmadan tek paketle PNG ve MP4 alma.
- Offline açılış, paket içi render runtime'ının eksik/bozuk olması, child crash,
  yeniden başlatma/fallback, uygulama kapanışında process temizliği, disk dolu,
  izin reddi ve bozuk recovery dosyası senaryoları.
- Web sürümünde çalışan sahne sözleşmesi masaüstünde farklılaşmaz; native-only
  capability UI'da açık görünür.

## 5. Öncelik 10 — import/export ve final render

### P10.0 — tek envanter ve golden fixture

- File, JSON, portable proje, MCP, runtime, raster, sequence ve Chorono Render
  giriş/çıkış yollarını tek tabloda gerçek destek durumuyla kaydet.
- Parent/pivot, mask/effect, text/font, image, spline, particle, Mesh2D,
  rigid/fracture bake, iki timeline, state/wire ve audio içeren küçük ayrık
  fixture'lar kullan; tek dev sahneye güvenme.
- Silent drop, farklı varsayılan, zaman/opacity birim farkı ve asset kaybını
  golden karşılaştırmada görünür kıl.

### P10.1 — canonical import/export kapısı

- Mevcut `RuntimeSceneCompiler` tek alan allowlist'i ve schema sınırı olur.
- File/JSON/MCP aynı version/profile/options normalizasyonunu kullanır.
- Legacy loader sürümlü ve açık migration tanısı üretir.
- Asset/font/audio dependency manifest'i ve capability/fallback raporu çıkar.
- Eksik zorunlu kaynak export'u durdurur; desteklenmeyen alan sessizce atılmaz.
- Portable save/open ve runtime export aynı source kimliği, zaman ve görünürlük
  anlamını korur.

### P10.2 — canonical frame ve yüksek kaliteli 2D render

- Viewport, Render Preview, raster/sequence ve gömülü Chorono Render aynı
  immutable frame request/evaluator sonucunu kullanır.
- FQ0: logical composition ile output/backing ölçüsü ayrılır.
- FQ1: path, text, mask/effect, particle ve Mesh2D hedef çözünürlükte yeniden
  çizilir; düşük çözünürlüklü bitmap büyütme final kalite sayılmaz.
- FQ2: `Final Native` 1× ve `Final High` 2× spatial sample + bounded downsample;
  aynı profil preview ve export'ta aynı kareyi üretir.
- Render Preview; progress/cancel, stale kaynak göstergesi, Fit/100% ve
  viewport/final karşılaştırması sunar.

İleri renk interpolation, global dither, CanvasKit ve uçtan uca FP16 bu kapıyı
bekletmez; [ana export planındaki](export-consistency-2d-plan.md) sonraki kalite
araştırması olarak kalır.

### P10.3 — desteklenen çıktı UI'ı

- `Export → Render…` tek Render Settings akışıdır.
- Tek kare: dahili PNG; uygulanmışsa WebP/JPEG capability ile gösterilir.
- Video niyeti: aynı uygulama içindeki Chorono Render MP4 finishing'i varsayılan
  olarak yürütür. Gömülü runtime başlatılamaz, çöker veya işi desteklemezse
  gerçek neden gösterilerek PNG sequence ZIP fallback uygulanır; dahili backend
  MP4 üretmiş gibi gösterilmez.
- UI, harici uygulama seçimi veya bağlantı ekranı göstermez. `Chorono Render —
  Integrated` durumu, motor/codec sürümü, progress, cancel, retry, fallback
  nedeni ve tanı/log eylemi aynı Render Settings/Jobs yüzeyinde gösterilir.
- Backend, çözünürlük, FPS, süre, background, alpha, profil, tahmini kare/byte,
  warning ve gerçek çıktı biçimi çalıştırmadan önce görünür.
- Alanların kalıcı etiketleri, klavye kullanımı, 44 px hedefleri, inline hata,
  odaklanabilir özet ve stable status alanı 2D UI sözleşmesini izler.

## 6. Öncelik 11 — hızlı çoklu çıktı ve otomasyon MVP'si

v0.6.0, tüm responsive layout veya içerik otomasyonunu değil, **mevcut çıktıların
güvenilir iş orkestrasyonunu** tamamlar:

- Tek kare, seçili aralık ve tam timeline render işi.
- Desteklenen raster/PNG sequence ve uygulama içindeki Chorono Render MP4 işi.
- Frozen source revision, timeline/range, output profile ve dependency snapshot.
- Bounded seri queue; queued/running/completed/failed/cancelled, progress,
  cancel ve explicit retry.
- Benzersiz güvenli dosya adı ve output manifest'i; source/profile/ölçü/FPS,
  warning, backend ve çıktı hash'i.
- Bir işin başarısızlığı diğer işi bozuk başarılı göstermez; scene ve undo
  render sırasında değiştirilmez.
- Kuyruk, gömülü render motorunun job kimliği, ilerleme, cancel, retry ve crash
  sonrası fallback/yeniden deneme tanısını sahiplenir; kullanıcı ayrı bir
  uygulamada iş takibi yapmaz.
- UI ve MCP aynı job/status/cancel sözleşmesini kullanır.

Şunlar bu v0.6.0 dilimine girmez: responsive variant compiler, üç oranı otomatik
reflow, component library genişlemesi, CSV/JSON data-driven batch, audio-driven
motion, otomatik beat, kelime zamanlı altyazı ve yeni codec geliştirmesi. Bunlar
Öncelik 11'in sonraki sürüm genişlemesidir.

## 7. Öncelik 12 — hedefli optimizasyon ve birleşik v0.6.0 kabulü

İkinci genel rewrite/profiler yapılmaz. Yalnız P10/P11 ve mevcut sistemlerin
ölçülmüş release engelleri düzeltilir:

- Render/import job cancellation, stale sonuç reddi ve lease/dispose temizliği.
- Output/native/encoded peak için preflight ve ortak kaynak bütçesi.
- Four Seasons ile playback, seek, Render Preview ve export CPU/bellek/visual
  regresyonu; eski ölçümle koşullar yazılmadan hız iddiası yapılmaz.
- Aynı representative karede viewport/preview/raster/sequence/MCP ve gömülü
  Chorono Render kaynak karesi karşılaştırılır.
- Temiz checkout'ta `npm test`, `npm run mcp:build`, `npm run build`; ilgili
  CLI değişmişse CLI build/test/pack.
- İzole portta gerçek UI + MCP; portable save/open ve tarayıcı konsolu kontrolü.
- v0.6.0 çıktı kabul matrisi oluşturulur; v0.5.0 regresyon fixture'ları temel
  olarak yeniden kullanılır ve PASS/FAIL/BLOCKED kanıtı kaydedilir.
- Paket sürümü, tag, public release veya yayın ancak ayrıca açıkça
  yetkilendirildiğinde yapılır.

## 9. v0.6.0 tamamlanma tanımı

Bu plan ancak şu koşulların tümü kanıtlandığında biter:

1. Mevcut editör/Mesh2D/bake/rigid/fracture projeleri açılır, düzenlenir,
   undo/redo ve portable round-trip yapar.
2. Seçilen masaüstü shell gerçek fixture ile ölçülmüş; native proje yaşam
   döngüsü, process, MCP, recovery ve desteklenen platform artifact'ı geçmiştir.
3. Import girişleri ile runtime/raster/sequence/MCP aynı canonical profile ve
   frame anlamını kullanır; silent data loss yoktur.
4. Render Preview ile kaydedilen kare aynı output profile'da görsel olarak
   eşleşir; Final High gerçek hedef çözünürlükte yeniden çizilir.
5. Chorono Render aynı masaüstü paketiyle kurulur ve uygulama tarafından
   başlatılıp kapatılır; ayrı launcher/discovery/elle bağlantı olmadan MP4
   üretir. Gömülü motor kullanılamazsa dahili fallback nedenini ve gerçek çıktı
   türünü açıklar ve başarılı olur.
6. P11 queue kaynak sahneyi değiştirmeden cancel/retry ve manifest üretir.
7. Test/build, gerçek UI/MCP, portable, görüntü, masaüstü install/reopen ve
   kaynak yaşam döngüsü kapıları geçer; bilinen sınırlamalar release notuna
   yazılır.
