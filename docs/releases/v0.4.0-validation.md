# v0.4.0 validation and limits

This report records checks for the GitHub source and CLI archive release. It does not claim every older spline roadmap item is implemented or that every output backend has separate visual acceptance for the new geometry.

## Source and integration

- Spline modeling, script/MCP exposure, Agent handoff and precision controls entered `main` through [PR #13](https://github.com/codie1982/chorono-editor/pull/13); 2D Snap/rotate corrections through [PR #14](https://github.com/codie1982/chorono-editor/pull/14). Both required **Tests and builds** jobs passed.
- Version, release notes and validation are prepared through [PR #15](https://github.com/codie1982/chorono-editor/pull/15). The final release commit and tag are recorded by GitHub rather than hard-coded here.
- The release does not change ordinary scene JSON schema for modeled splines. Offset/Outline create standard sibling spline layers; Chamfer/Fillet leave standard editable spline topology. Existing renderer, portable project and exporters consume that representation.

## Browser and geometry acceptance

- A rectangle spline was tested in the real editor. Offset Preview and Apply created a second layer; one Undo restored the original layer count.
- Fillet and Chamfer Preview/Apply were inspected on all four rectangle corners in the canvas. Outline Preview/Apply produced a visible band as a sibling layer. Each test edit was undone in the disposable test scene.
- Geometry tests cover outward/inward rectangle offsets, open left/right offsets, closed/open outlines, collapse and overlap rejection, corner topology, curved input approximation, one-command Undo/Redo and QuickJS scripting round trips.
- The panel rejects stale source revision/document changes before Apply, and corner replacement rejects tracks addressing the chosen contour. These guards have unit/script coverage; a dedicated cross-session browser conflict run was not performed.

## Known limits

- Bézier edges are flattened at a 0.25 layer-local pixel target until the subdivision cap. Fillets between curved edges use a G1 cubic approximation; the requested radius is exact only for two straight edges.
- The preview is inside the modeling dock panel. Very large or degenerate contours, self-intersections, collapsing offsets, overlapping cuts and animation-addressed contour replacements are rejected rather than partially committed.
- Portable save/load and SVG/runtime/raster exports use the existing spline paths, but the new modeled results were not separately inspected across all output formats. Existing exporter capability warnings remain applicable.
- Full Point/Edge/Object selection modes, Boolean preview/re-edit, the complete topology tool suite, Auto Close and drawing to connect open ends were not verified as shipped features in this source release.
