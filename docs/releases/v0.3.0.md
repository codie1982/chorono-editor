# Chorono v0.3.0 — Editable animation workflows and safer agent collaboration

Released 12 November 2026. [Türkçe](../tr/releases/v0.3.0.md) ·
[Validation and limits](v0.3.0-validation.md) · [Changelog](../../CHANGELOG.md)

This release brings the completed pre-3D work into `main`: refine agent-created
scenes by hand, preserve those edits on subsequent MCP changes, and continue
editing after a page reload. The existing 2D editor remains the active workspace.

## Viewport authoring

- Corrected pivot/anchor transforms, selection feedback and first-drag/pointer
  release handling, including guide dragging and continuously placed shapes.
- Edit animation paths and position key points in the viewport with Timeline
  synchronization. Existing key identity, easing and unrelated tracks are retained.
- Alt-drag copies complete selected subtrees and their animation/references.
  Mouse release commits while Alt remains held. Parent/child selections are
  deduplicated and the operation is one undo step.
- Multi-selection Array supports linear, radial and path placement, preview,
  Apply/Cancel and one-step undo while preserving descendant animation.
- Editable horizontal/vertical nearest-neighbor gaps, persistent ruler guides,
  guide locking/hiding and off-artboard editing with dashed outlines.
- Pan controls share a previous-tool toggle (M or H). Viewport buttons retain
  their own pointer events; cursor guides stay out of controls and other panels.
- Grouped Project/Export actions and contextual spline continuation reduce toolbar
  duplication. Motion Keys appears when a suitable object is selected.

## Timeline, hierarchy and procedural motion

- Shared Scene Explorer/Timeline hierarchy, subtree operations, explicit
  **Find in Timeline**, and temporary branch isolation without changing source
  visibility or exported scene data.
- Prominent **Set Key** with hold/menu channel selection; batch key operations,
  collision-aware editing and expanded frame/key/start/end navigation.
- Track context actions clear animation with undo. Procedural numeric curves
  can be previewed and baked to editable native keys with sampling/error limits.
- Fixed topology path/spline point animation remains distinct from topology
  morphing; a registry entry alone is not treated as a new finished object type.

## Expressions and input calculations

- Saved numeric formulas, live expressions for supported typed visual properties
  (number, boolean, string, color and Vec2), named sources and explicit errors.
- Expression evaluation shares the scene's time/parameter context in the editor
  and supported full-scene Web SDK/render paths.
- Preview, convert to an authored value, retain the authored fallback, or bake
  supported property expressions into native keys. Discrete values use hold keys.
- **Calculate once** evaluates an operation setting without retaining a formula
  or starting a live configuration job. Lifecycle/import settings are not made
  reactive merely because an input supports calculations.

## Recovery, collaboration and diagnostics

- Autosave committed scenes and restore the last local session on reload.
  Session IDs identify local storage, save outputs and session history.
- Persist bounded Undo/Redo history: up to 50 combined steps and approximately
  64 MiB of estimated source data. Browser recovery is not a substitute for an
  external portable project; storage failures remain visible.
- MCP 2.1 requires a current `get_scene` revision and one-use `readToken` before
  source mutations. A native batch uses one outer authorization; a script dry run
  returns a new plan-bound token. Stale edits fail rather than replacing manual work.
- Source provenance records creation and latest human/agent field writers,
  including copy inheritance, without embedding actor flags in animation values.
  Missing provenance means unknown and never grants overwrite permission.
- Improved typed MCP schemas, parameter/result documentation and focused tool
  discovery. Preferred aliases coexist with historical tool names; current
  read/revision guards apply to both.
- Bounded interaction diagnostics and consent-controlled anonymous summary
  queue, receiver/storage API, version checks and a grouped issue panel with
  **New / Investigating / Fixed** states and repeat counts. Consent persists;
  delivery is disabled without consent. A public receiver deployment is separate.
- Refreshed startup demo and contextual Help links to 58 canonical documentation
  targets, reusing the shared control. Production panel/dialog fixtures support
  repeatable documentation captures; the website is maintained separately.

## Validation and boundaries

The [validation report](v0.3.0-validation.md) records fresh merge checks and the
prior native/browser acceptance. The Four Seasons ten-play acceptance remained
within the same 512 MiB managed-resource policy (46.25 MiB observed peak).
Measured CPU times differ from historical v0.2.0 runs; this release does not
claim a general CPU speed improvement or a total browser/OS memory cap.

Final raster output renders source layers, not viewport LOD proxies. Existing
exporters retain their documented limits: resolution scaling is not yet a new
resolution-independent renderer; basic SVG/native runtimes do not support every
live expression/effect. Review exporter warnings or explicitly bake/convert.

Boxed 3D, Poly/UV/Blob, new cloth/fluid/fracture solvers, CFX compositing/tracking
and full Export E0 remain planned. This release does not enable a 3D workspace.

## Install this version

Requires Node.js 20+, npm, Git and a modern browser:

```sh
git clone --branch v0.3.0 --depth 1 https://github.com/codie1982/chorono-editor.git
cd chorono-editor
npm ci
npm run cli:build
npm run chorono -- setup
npm run chorono -- start --background --open
```

Connect the browser using **MCP → Connect this editor**, reload the agent's MCP
connection, then run `npm run chorono -- doctor`.

The GitHub release includes the checked `@codie1982/chorono@0.3.0` CLI tarball,
a validation receipt and SHA-256 checksums. The root editor stays private; this
GitHub publication does not publish either package to the npm registry.
