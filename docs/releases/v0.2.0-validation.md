# v0.2.0 validation and measurement scope

This versioned report summarizes the original implementation acceptance and the
release integration checks. Local raw browser reports remain under ignored
`artifacts/`; a fresh clone includes protocols and harness source, not private
project files, Task Manager captures, local paths or process telemetry.

## Implementation acceptance

The original Four Seasons fixture has 4,079 layers, 42,512 keys, two timelines
and a 48-second main animation. A separately compiled production EditorPage used
the actual React/CSS/editor dependency graph. It warmed for more than 60 seconds,
then completed ten whole plays in 490 seconds with zero hidden-document samples.

Raw DOM progress aligns process samples only to approximately ±2 seconds. Heap,
managed bytes and RSS overlap and must not be summed. No forced Chrome GC was
used. The earlier 37 GB report's cause was not established, and no all-browser,
decoder or driver hard RAM cap is claimed.

Fifty separate property commits were followed by 50 undo, 50 redo and 50 final
undo operations. Every displayed value was checked. Native saved scene files
matched the original bytes after seek/pan/zoom and editing. New Scene reached
zero layers/timelines; reopen restored all 4,079 layers and two timelines.

After unmount/reclaim, the shared ledger, source references, pending and failed
source counts were zero. The last ten seconds of the idle observation recorded
zero draw/evaluation intervals. Intervening playing samples were excluded from
the idle claim rather than presented as a controlled idle period.

## Panel cost and retained source regression

Overview panel whole-page RAF p95 was 67.6 ms against an initial inactive
66.7 ms (+1.35%). A later inactive control reached 233.4 ms. Two-full-cycle
synchronous viewport p95 values were 42.8 / 53.7 / 175.4 ms. These noisy samples
do not establish a universal causal overhead percentage or an FPS guarantee.

Separately, the renderer-only two-placement comparison retained 120 paired
samples and 12 exact RGBA checkpoints: p95 222.1→207.4 ms. An identical-byte
A/A control also varied, p95 229.1→332.8 ms. Inclusive stage tracing was retained
for diagnosis, not added together as independent CPU totals. No new drawing
algorithm was invented to explain an unproven OS/noise cause.

A real ownership regression was fixed: a paused ProjectResourceMonitor retained
the previous project's scene identity until the next read. Its input adapter now
invalidates cached counts/identity immediately on scene replacement. A separate
Node explicit-GC regression collected 0/20 old scenes before the fix and 20/20
afterward, while preserving 20/20 current borrowed scenes. This test does not
change Chrome or production GC settings. Exact browser collector retained bytes
remain unavailable; bounded numeric snapshots are not total scene heap.

- LOD output: 26/26 checks including warmed global viewport cache, actual PNG

  export LOD groups. Source JSON stayed unchanged.
- Output integration: 21/21 native checks plus 9/9 production MCP file-transfer
  receipts, actual download hashes, cancellation/stale handoff and cleanup.
- The source-level acceptance suite passed 262 files / 2,093 tests, TypeScript,
  MCP and Next builds. The final local evidence audit passed 31 named checks.

The long run and final panel builds were preserved independently; final UI text
and collector changes were not misrepresented as identical old bundle bytes.
Subsequent `main` integration and the version bump receive fresh release checks.

## Reproducing checks

```sh
npm ci
npm run cli:build
npm test -- --maxWorkers=2
npm run cli:test
npx tsc --noEmit
npm run mcp:build
npm run build
node scripts/perf/monitor-retention.mjs artifacts/monitor-retention
npm run cli:pack
```

Stop the editor's Next server before dependency installation or builds. The
browser harnesses under `scripts/perf/` require the fixtures described in their
protocols; local fixture files are deliberately excluded from the source release.
`AGENTS.md` defines the canonical coding, validation and handoff rules.

The release PR must pass **Tests and builds** before merge. The final merged SHA,
tag and CI run are recorded in the published GitHub release. CLI packaging is
checked independently; the private editor root is not published to npm.

## Release integration checks

The release worktree was merged with current `main`, including its CI workflow,
community templates and security-reporting guidance. A clean `npm ci` completed.
On the integrated v0.2.0 source:

- 262 unit-test files / 2,093 tests passed with two workers.
- All 16 CLI tests passed, including local mock-server lifecycle cases.
- TypeScript, bundled skills, MCP and editor production builds passed.
- The separate paused-monitor ownership regression passed 20/20 cases.
- The actual CLI tarball contains 18 allowlisted files. Its extracted executable
  passes `--help` and `skills list --json`, reporting version `0.2.0` and both
  bundled skills. Source projects, editor files and dependency trees are excluded.
- Release-document local links and package/lock versions were checked.

The initial sandboxed CLI run could not bind its loopback test servers; it was
repeated successfully with the required local permission. Packaging used a
dedicated writable npm cache rather than changing global cache permissions.
These environment failures are not presented as product test failures or hidden
passing runs. The GitHub PR's CI result supplies the clean Linux verification.
